# GitHub 发布检查清单

从这个独立目录发布，仓库根目录包含 `README.md` 和 `skills/`。不要把学习工作区、原始材料目录或个人配置目录整体上传。

## 发布内容

- `README.md`：用途、依赖、安装和示例。
- `CONTRIBUTING.md`：规则修改与案例脱敏方式。
- `skills/method-ppt/`：技能入口、界面元数据和三个参考文件。
- `.gitignore`、`.gitattributes`：排除任务产物与本地配置，约定文本换行。
- 本检查清单及 MIT 许可证 `LICENSE`。

## 发布前核验

- [ ] 已确定仓库名、公开或私有，以及许可证；README 的许可说明与 `LICENSE` 一致。
- [ ] 技能入口能通过当前环境可用的结构校验，相对链接和引用文件存在。
- [ ] README 说明配套工具与技能未打包，不承诺未经验证的宿主兼容性。
- [ ] 对整个发布目录运行隐私与密钥扫描，逐条检查发现项，并确认没有扫描错误或被忽略的风险文件。
- [ ] 扫描报告、私人词典、备份、论文、截图、PPT、讲稿和个人配置均不在待提交内容中。
- [ ] 人工复查案例与研究启发，保留通用规则，移除未公开的具体构想和身份信息。
- [ ] 如使用 Git，检查暂存内容及提交身份是否符合公开发布意图；存在历史时也检查历史中的敏感内容。

`.gitignore` 只帮助避免新增文件被误收录，不能清除已经跟踪的文件或历史内容。扫描无发现也不能替代对研究内容与材料授权范围的人工判断。

## 上传与检查

通过 GitHub 网页或 Git 工具上传该目录内的发布文件。使用网页时也要确认两个点号开头的配置文件已包含在内；网页选择文件不依赖本地 `.gitignore` 保护。

首次上传后打开 README，检查中文、表格、目录和相对链接。再从仓库下载一份，在独立位置检查 `skills/method-ppt` 的文件结构；能运行相应工具时，按 README 的小任务检查技能发现与使用情况。

每次修改后重新核验实际发布的文件。旧版本检查通过，不代表新加入的案例或附件也已检查。
