# 专用个性化讲解型PPT

把材料整理成用户能理解、能直接讲、听众能跟上的演示文稿。交付实际要求的文件，不停在精读报告、大纲或生成提示词。

本技能负责内容取舍、个人偏好和修改纪律；实际读写PPT、渲染及导出遵循当前环境的演示文稿专用技能。它不固定某篇论文的目录、模板、算法或页数。

## 使用优先级

1. 本次用户的明确要求与指定原话。
2. 当前文件、最新批注及本次材料所支持的事实。
3. 下列个人默认偏好。
4. 通用演示设计建议。

用户问“什么意思、为什么有这个、是不是论文的数据”时，先在聊天解释。只有明确要求修改，或正在授权的修改范围内，才把回答写进PPT。

## 个人默认偏好

- 主要听众是同门或课堂同学；中文讲解，语气平实，先讲具体动作，再介绍术语。
- 先说明完成什么工作、解决什么问题、适用于什么场景，再沿整个任务的输入、训练、输出和应用讲方法。
- 方法逻辑优先；实验用于检验方法，理论证明通常不展开。用户要求理论分享时相应调整。
- 每页文字适量、分点清楚；概览分别讲“解决了什么问题”和“提出了什么方法”，正文保留必要的学术表达。关键符号首次说明，已定义的符号不反复释义。
- 公式和算法优先使用指定版本的原文截图，旁边添加可编辑的解释。公式解释计算关系、各项作用和引入目的。
- 关键公式默认采用“完整原式＋对应项下方的可编辑括号＋简短作用说明”：按计算含义分组，解释各项做什么、为何引入，不只释义字母。完整公式只展示一套，长式可按逻辑分行；具体标注与排版见[公式规则](references/content-and-design.md#4-公式讲明怎么算为什么算)。
- 公式及解释中的变量采用相同的标准数学字形，保留大小写、上下标与字体类别；说明统计范围、参数作用和输入输出，避免用普通字母串替代数学符号。
- 算法说明对应准确行号，讲明各段做什么、为什么做、产生什么结果。优先查找正文、附录及官方补充材料中的伪代码；自行整理时以公式和控制结构为主，并标明来源性质。
- 实验设置、结果表格和图默认截取原论文，按模板中的图文关系摆放；分别解释各子图及其结论，保留图例、坐标、误差和比较条件。
- 已有模板沿用，包括母版、标志、字体、配色与标题层级。新稿采用清楚、克制的视觉层级，避免无关图标、装饰和底部总结套话。
- 中文正文、结论与讲稿写完后默认用 `humanizer-zh` 检查空话、重复与生硬表达，保留事实、限定和研究语气；用户指定原话直接照用。
- 不在每页堆放“PDF第几页、原文式几”等来源标签；必要引用按场合放在备注、参考文献或轻量署名中，不抹去证据来源。
- 口播稿对应最终PPT的实际页序，句子简洁直接，能自然读出；不把聊天中的所有知识解释塞进页面。

这些是可覆盖的偏好。署名仅使用本次任务明确提供的信息，未提供时留空；不默认填入姓名、年级、学校或小组，也不从历史对话推断后写入新产物。已有封面信息以用户要求为准。术语、配色、页数和版式均随材料调整。

## 开始时先定位任务

从对话和文件中确认：当前版本、材料版本、汇报场景、听众基础、时长或页数、模板、重点、交付范围。只追问影响正确完成任务且无法合理推断的信息，不要求用户填写整份问卷。

- **从零制作**：读下面的制作流程，以及 [内容与设计](references/content-and-design.md)。
- **现有PPT批注修改**：先读 [修改与口播](references/revision-and-narration.md) 中的修改规则，保留未涉及页面。
- **公式、算法、实验或研究启发的专项改写**：读取 [内容与设计](references/content-and-design.md) 中对应部分，不把专项修改扩大为整稿重做。
- **只重写稿子**：先读取最终PPT，再读该参考文件中的口播规则，不重新设计演示文稿。
- **所有文件交付前**：使用 [验收标准](references/quality-checks.md) 中与本次产物有关的检查项。

## 工具与技能配合

按当前会话可用目录选择并读取需要的专用技能，不凭记忆硬编码工具接口或插件版本路径。

- 生成或编辑PPT：当前环境提供 `presentations` 时遵循其要求；未提供时选择可用的演示文稿专用技能。需要 `ppt-master` 的模板、原生编辑或制作流程时读取相应入口并遵守其路由。科研页面的信息组织可配合 `scientific-slides`。
- 理解论文：工作区的 `paper-reading-zh`；只有用户需要完整精读笔记时才扩展为笔记任务。
- 检查中文草稿与改写文本：`humanizer-zh`；英文稿使用适用的英文润色技能。先成稿，再润色并对照材料核实语义；公式、数据与用户指定原话不进入自由改写流程。
- 读取、截图或生成PDF：适用的PDF专用技能。用户只要PPT时，不附加生成整套稿件和PDF。

只加载当前阶段需要的技能。实际接口、绑定会话、导入导出和验证规则以所选专用技能为准；本技能不授权绕过它们，也不额外授权外发或删除文件。

## 制作流程

### 1. 阅读材料，建立依据

论文任务先核对摘要、方法、算法、实验和局限的相关内容，定位将使用的截图。已有PPT先取得实际页序、标题、正文、图片及备注，识别哪些是用户已确认的设计。

把关键主张分清为原文结论、实验结果、自行推导、教学假设或个人评价。内部保留每条关键主张对应的位置和版本；没有证据的数字、测量结果和“作者提出的方向”不写成论文事实。

### 2. 确定讲述顺序

围绕“问题与场景 → 作者工作 → 整体方法 → 核心机制 → 算法如何执行 → 证据与局限”组织。按本次主题合并、删减或重排，避免机械照抄论文章节。

每页只承担一个清楚的讲解任务。方法主线覆盖整个应用过程，而非仅列训练算法名。多方法比较先交代共同目标，再交代关键操作差异。

### 3. 设计每页内容

为每页明确：听众应理解什么、用哪个原文或图证明、页面写哪些话、哪些解释留给口播。用 [内容与设计](references/content-and-design.md) 选择适合公式、流程、对比或结果的组织方式。

左图右文是可选布局，不是所有页的固定格式。优先保证原文截图和算法行号看得清；装不下时拆页或收紧说明，不靠缩小字体硬塞。

### 4. 制作文件并检查

沿用模板的主色、标题和留白关系，正文、标注、流程和比较内容尽量可编辑，原文截图保持图像形式。制作过程中检查完整公式、图文对应及跨页衔接；完成后按专用技能渲染，逐页检查。

### 5. 按需写稿

只有在最终PPT页序明确后才写配套稿；覆盖封面、论文信息页、章节过渡和结束页。实际页码与“1.1”等章节编号分别记录，避免错位。详细规则见 [修改与口播](references/revision-and-narration.md)。

### 6. 核验并交付

执行 [验收标准](references/quality-checks.md)，修正发现的问题。简短说明产物、实际验证和关键路径；没有完成的检查明确说明。

“就在这个PPT改”表示交付到指定文件；可在内部保留可恢复副本，验证后更新原位置，不擅自生成多个公开版本。临时材料放在任务内的构建目录。只有明确要求清理时，才在核实范围后清理；保留用户原始材料和必要来源。

## 调用示例

- “使用 `$method-ppt`，根据这篇论文和这个模板做15分钟的组会PPT，重点讲方法。”
- “使用 `$method-ppt`，按这三条批注改当前文件，左边截图保留，文字用我的原话。”
- “使用 `$method-ppt`，读取最终PPT写逐页口播稿，并导出适合手机阅读的连续排版PDF。”
