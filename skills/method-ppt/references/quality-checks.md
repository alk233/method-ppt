# 验收标准

按本次范围选择检查项。这里补充内容和编辑质量要求，不替代当前PPT、PDF技能的技术验收。生成成功或文件能打开，不等于内容已验证。

## 新稿：内容

- [ ] 当前材料、翻译版本和模板已经确认，未误用旧稿或其他版本截图。
- [ ] 前部说明具体问题、作者工作和场景，方法主线覆盖完整任务。
- [ ] 核心机制包含具体操作与作用，没有只写“提升效率”等抽象描述。
- [ ] 公式完整且不重复；关键项默认有对齐的可编辑下括号与作用说明，明确输入、运算、输出及关键系数的作用，采用其他标注形式时同样对应清楚。
- [ ] 公式与说明中的大小写、上下标及数学字体一致；关键参数、集合与算子已定义，统计对象、维度和输出层级明确。
- [ ] 总体目标、实际训练损失、测试评分与判定规则已区分；超参数是否学习、阈值来源和分数方向有依据。
- [ ] 算法截图和行号对应，客户端与服务器的职责、参与范围、循环和传输内容准确。
- [ ] 算法来源性质清楚；整理稿以数学更新和控制结构为主，核心设计已在主过程或子过程中体现，输入、模型参数、簇和测试集等关键量有说明。
- [ ] 需要复用分组或切换阶段时，状态更新、复用对象与恢复条件明确，没有把固定分组写成冻结模型。
- [ ] 数据、推导和示例归属清楚；无自编实验数据，无无依据的作者结论或未来工作。
- [ ] 比较指标回答汇报问题，准确率、通信量和耗时没有互相替代；重要实验条件已保留。
- [ ] 实验设置与结果使用所需原文截图，每个子图有对应解释，数据集、集合、领域与IID／non-IID设置区分清楚；消融覆盖主要变体及结论范围。
- [ ] 概览、总结与局限分点清楚；研究启发区分报告已有工作与个人设想，说明具体机制和待验证问题。
- [ ] 中文草稿已按 `humanizer-zh` 检查，并复核数据、条件、比较对象、限定与归因未改变；用户指定原话保留。
- [ ] 理论、实验和细节的篇幅符合本次要求；未机械复制旧稿页数或目录。

## 新稿：视觉与文件

- [ ] 按专用技能完成导出验证并实际渲染，逐页检查新稿。
- [ ] 中文、数学符号和上下标正常；无遮挡、溢出、意外换行、模糊公式和图像拉伸。
- [ ] 重点截图足够大、关键图例与算法行号可读；布局没有迫使听众跳读。
- [ ] 沿用模板的母版、标志、字体和标题层级；同级小标题的字号与样式一致，重复页面已按本次要求合并。
- [ ] 可编辑正文与标注保留；没有将整稿压成不可编辑的图片替代用户要求的PPT。
- [ ] 署名、标题语言、目录与页码正确；无未要求的图标、来源页码标签或重复口号。

## 局部修改

- [ ] 每条批注已对应目标，提问与编辑请求已区分。
- [ ] 原话替换逐字核实，格式修正没有顺带改写正文。
- [ ] 只改授权区域，原图和指定保留对象仍在；删除或移动页面后的内容没有丢失。
- [ ] 渲染检查受影响页，并确认其他页面与保留区域没有意外变化。
- [ ] 内联文字、公式符号与标点之间没有新增重叠；被遮挡对象已区分源图截断、裁切与图层问题，修复后完整显示。
- [ ] “原文件修改”交付到指定路径；内部临时文件未被当成多个公开版本交付。
- [ ] 使用用户最新指定的版本，未误写历史路径；聊天提问得到回答，未自动扩大文件修改范围。

## 口播稿与PDF

- [ ] 依据实际最终PPT逐页写稿，包含封面、过渡和结束；标题和页序一致。
- [ ] 指示词、公式编号、算法行号、结果数值与画面一致。
- [ ] 口播稿默认使用平淡、流畅的叙述语气；具体动作和因果清楚，没有“那如何解决这种问题呢”等设问口癖、机械过渡与夸张套话。
- [ ] 新写或改写的口播稿已使用 `humanizer-zh` 检查，并通读核实句间、页间衔接及事实与结论的确定程度。
- [ ] 用户替换稿完整保留，无漏段；页码差异已核对并按授权处理。
- [ ] 手机稿PDF连续排版，文字可选取，字体正确；导出后的完整文本和跨页显示已核验。

## 用于检查技能行为的场景

这些是制作决策的校验案例，不要求为每次任务额外生成测试PPT。

1. **用户问“这里为什么有SGD？”**
   应读取相关页，解释这个优化器在此处的作用以及是否影响理解；没有编辑授权时不自动增加一块解释或删除它。

2. **用户说“就把这一句换成我写的，左图别动”。**
   应逐字替换该句并核查布局，保留图片及裁切；不能重新总结整页。

3. **用户要给优化目标加解释。**
   应保留完整原式，用可编辑括号标注各项作用；不能重复摆放原式与一整套重排公式。

4. **用户追问“这个压缩倍数是论文实验吗？”**
   应核对来源，清楚说明是论文测量、按原文条件推导还是自设算例；不能给假设结果补造实验依据。

5. **用户删页后要求重写口播。**
   应重新读取实际最终文件的物理页序，再写逐页稿；不能沿用旧稿页码。

6. **用户换成另一门课或另一篇论文。**
   应重新决定问题、主线、评价指标和页型，继承讲解与修改习惯；不能继续套旧论文的术语或主题。

7. **用户问“这里统计的是本地全部图，还是全部客户端？”**
   应核对公式，分别说明集合成员、运算范围和输出用途；不能仅重复变量名称，也不自动修改PPT。

8. **用户要求去网上找原文算法。**
   应检查相关正文版本、附录和官方补充来源；没有找到时限定结论范围，自行整理需注明，不伪称作者原算法。

9. **用户说“这个字母被遮住了”。**
   应同时检查源图和摆放；源图截断时更换完整符号，不能只把残缺图片置顶。保持相邻文字及其他页面不变。

10. **用户要求图中的(a)、(b)都讲清楚。**
    应分别说明设置、图中元素、观察和共同结论；不能用一段泛泛的“展示相似性”代替。

11. **用户要求把长期修改偏好写入技能。**
    应合并成可复用的制作与验证规则，去掉重复；具体论文名、一次性的页数与文件路径留在当次任务，不变成固定模板。

完成后仅报告实际执行的检查。结构校验通过不能写成已经验证过全部真实制作场景；缺少渲染或来源核查时说明具体限制。
